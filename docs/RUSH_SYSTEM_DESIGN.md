# 进货市场抢购管理系统设计文档

> 核心目标：严格按照「时段参数配置」规则执行抢购流程，每个时段参数独立生效、无缝切换，所有抢购行为均受对应时段参数约束。

---

## 一、系统总览

### 1.1 架构分层

| 层级 | 职责 | 实现位置 |
| --- | --- | --- |
| **配置层** | 时段参数的存储与管理（CRUD） | `rush_time_slots` 表 + `FlashBuyManagePage` |
| **生效层** | 参数的实时读取、时间点自动切换、重叠仲裁 | `MRushPage`（客户端渲染）+ Realtime 订阅 |
| **校验层** | 抢购下单时的参数校验（服务端权威校验） | `getRushPhaseAndLimit` + `handleFlashBuy` |
| **异常层** | 时段切换、并发、库存耗尽等异常处理 | 下单流程的原子校验与兜底 |

### 1.2 数据模型

```sql
rush_time_slots (
  id            uuid PK,
  name          text,          -- 时段名称（早场/主场/…）
  start_minute  int,           -- 开始分钟（北京时间，0-1439）
  end_minute    int,           -- 结束分钟（北京时间，0-1439）
  stock_limit   int,           -- 该时段全局库存限额（可下单总量）
  price_discount numeric,      -- 价格折扣（寄卖价 × 折扣 = 抢购价）
  priority      int,           -- 优先级（升序，小者优先）
  is_active     boolean,       -- 是否启用
  updated_at    timestamptz    -- 最后更新时间（重叠仲裁依据）
)

orders (
  ...,
  is_rush       boolean,       -- 是否抢购单
  rush_slot_id  uuid           -- 归属的抢购时段（用于库存核算）
)
```

**关键设计**：`orders.rush_slot_id` 将每笔抢购单归属到具体时段，使「全局库存限额」可按时段独立核算。

## 二、时段设置（开始/结束时间、库存限额、价格参数）

### 2.1 参数定义

| 参数 | 含义 | 约束 |
| --- | --- | --- |
| `start_minute` / `end_minute` | 时段起止（北京时间分钟） | `0 ≤ start < end ≤ 1439` |
| `stock_limit` | 时段全局库存限额 | `> 0`，该时段所有用户合计可下单总量 |
| `price_discount` | 价格折扣系数 | `0 < discount ≤ 1`（可扩展为加价 `>1`） |
| `priority` | 优先级 | 升序，小者优先；同优先级按 `updated_at` 仲裁 |
| `is_active` | 启用状态 | 关闭后立即不参与匹配 |

### 2.2 校验规则（管理端保存时）

1. `start_minute < end_minute`
2. `stock_limit > 0`，`0 < price_discount ≤ 1`
3. 分钟值在 `0–1439` 范围内
4. **重叠检测**：与已有时段区间相交时弹窗确认，确认后允许保存（新配置生效，体现"以新的诉求为准"）

### 2.3 多时段并行

- 支持同时配置多个时段（如早场、主场、午场）
- 同一时刻可能有多个时段命中 → 由「仲裁机制」选出唯一生效时段
- 每个时段的 `stock_limit`、`price_discount` 独立核算、互不影响

## 三、参数生效机制（配置时间点自动切换）

### 3.1 客户端实时计算

- 每秒刷新 `now`，根据北京时间分钟数匹配当前生效时段
- **无状态匹配**：每次渲染都从最新 `timeSlots` 重新计算，天然实现"到点自动切换"
- 无需定时任务、无需重启，时间一到 `currentSlot` 自动变更

### 3.2 重叠仲裁（以最新配置为准）

当多个启用时段在同一时刻重叠时，按以下优先级选出唯一生效时段：

```
1. updated_at 最新者优先（最近修改的配置生效）
2. updated_at 相同时，priority 小者优先
```

这保证管理员每次保存/新增的时段都会立即成为当前生效配置。

### 3.3 配置变更实时下发

- 对 `rush_time_slots` 表建立 Realtime 订阅
- 管理端任意修改（增/删/改/启停）后，所有在线抢单页**即时收到变更并重新拉取规则**
- 配合每秒渲染，实现"修改后立即生效，无需刷新或重启"

### 3.4 服务端权威校验

客户端计算仅用于展示；**下单时以服务端实时查询为准**：
- `getRushPhaseAndLimit` 在下单瞬间重新查询数据库，获取最新时段配置与库存
- 防止客户端状态过期或被篡改

## 四、抢购过程中的参数校验（防止超配置限额）

### 4.1 双重限额模型

| 限额类型 | 含义 | 校验方式 |
| --- | --- | --- |
| **全局时段库存** `slotRemaining` | 该时段所有用户合计可下单量 | `stock_limit − 当日该时段已下单数` |
| **单用户日上限** `todayCnt < dayLimit` | 单个用户当日下单数 | `dayLimit = stock_limit`（单用户不超过该时段限额） |

### 4.2 下单校验流程（`handleFlashBuy`）

```
1. 身份校验：登录 + 实名认证（KYC）
2. 获取当前权威状态：getRushPhaseAndLimit（服务端实时查询）
   → phase / slot / slotRemaining / todayCnt / dayLimit
3. 时段校验：
   - phase='none' → "当前非抢购时段"
   - phase='ended' → "今日抢购已结束"
4. 库存校验（核心）：
   - slotRemaining ≤ 0 → "该时段库存已抢完"
5. 单用户上限校验：
   - todayCnt ≥ dayLimit → "今日抢单已达上限"
6. 价格应用：finalPrice = consignment_price × slot.price_discount
7. 写入订单：含 rush_slot_id（归属时段）
8. 后处理：清除"未抢"标记、标记商品已购、Realtime 通知
```

### 4.3 老板（is_super_admin）豁免

老板账户完全绕过时段与限额校验，用于测试与运营操作。

### 4.4 原子性说明

当前采用「查询库存 → 写入订单」的乐观校验。在极高并发下存在轻微超卖窗口；如需严格防超卖，可升级为：
- 专用库存计数表 + 原子递减（`UPDATE ... SET sold = sold + 1 WHERE sold < stock RETURNING`）
- 或 Postgres 行级锁的事务函数

（当前业务并发量下乐观校验足够，设计已预留升级路径。）

## 五、异常处理（时段切换时的订单处理逻辑）

### 5.1 时段切换竞态

**场景**：用户在 09:29:59 点击抢购，请求到达服务端时已是 09:30:01（时段已切换）。

**处理**：服务端在请求处理瞬间重新计算当前时段，以**请求时刻**的生效时段为准：
- 若已切换到新时段 → 应用新时段的参数（价格、库存）
- 若已无生效时段（`phase='ended'`/`'none'`）→ 拒绝并提示"时段已结束/当前非抢购时段"

用户端展示的时段与实际下单时段可能不一致，但**最终以服务端权威结果为准**，不会产生越权订单。

### 5.2 库存耗尽竞态

**场景**：A、B 两用户同时下单，库存仅剩 1 件。

**处理**：先完成的写入归属该时段（`rush_slot_id`）；后到的请求重新查询时 `slotRemaining ≤ 0`，被拒绝。极端并发下可能轻微超卖（见 4.4），可通过原子计数升级消除。

### 5.3 订单归属与核算

- 每笔抢购单写入 `rush_slot_id`，明确归属时段
- 库存核算：`count(orders WHERE rush_slot_id = slot.id AND created_at ≥ 今日0点)`
- 时段删除时 `rush_slot_id` 置空（`ON DELETE SET NULL`），历史订单保留

### 5.4 失败回滚

- 订单写入失败 → 不触发任何后处理（商品不标记、标记不清除）
- 仅在写入成功后才执行后处理，保证数据一致性

### 5.5 无缝衔接保证

- 时段参数独立存储，切换时仅 `currentSlot` 指针变化，无状态迁移
- 前一时段的已下单记录通过 `rush_slot_id` 独立核算，不影响新时段库存
- Realtime 保证所有客户端同步看到最新配置，无中间态

---

## 六、无缝衔接总结

| 维度 | 机制 |
| --- | --- |
| 参数独立 | 每个时段一行独立配置，字段互不干扰 |
| 自动切换 | 每秒无状态匹配，到点自动变更 `currentSlot` |
| 重叠仲裁 | `updated_at` 最新 + `priority` 最小 |
| 实时下发 | Realtime 订阅，修改即时生效 |
| 服务端权威 | 下单瞬间重新查询，防篡改防过期 |
| 库存独立 | `orders.rush_slot_id` 按时段核算 |
| 异常兜底 | 切换竞态以请求时刻为准，失败不产生副作用 |
